# FIRe Lab — instructions for agents

FIRe Lab is a local spaced-repetition app. It schedules lessons and reviews over a knowledge graph: FSRS-6 models memory, and FIRe (fractional implicit repetition) counts a solved lesson as partial review of the simpler ideas it contains. **There is no built-in curriculum.** All content is *packs* the learner (usually through you) adds to `packs/`. There is no production deploy and no accounts; progress lives in `data/progress.db` on the learner's machine.

These instructions are for any agent (Claude Code, Codex, Cursor, Copilot, Gemini CLI, …). `CLAUDE.md` only imports this file.

## Run

- `./fire dev` (Windows: `fire dev`) — API + web app with hot reload at http://127.0.0.1:5190. Needs Go 1.25+ and Node.js 20+; the first run installs web dependencies.
- The app reloads packs by itself a few seconds after a file changes. No restart, no rebuild.

## Repository map

| Path | What | Edit? |
|---|---|---|
| `packs/<id>/` | The learner's packs (git-ignored) | **Yes — this is where content goes** |
| `examples/packs/softmax/` | A small complete pack to copy from | Only to improve the example |
| `docs/api.md`, `docs/pack-format.md`, `docs/pack.schema.json` | Generated by `./fire docs` from `server/*.go` | Never by hand |
| `.claude/skills/` | Generated mirror of `.agents/skills/` | Never by hand |
| `server/` | Go: packs loader and validator (`pack.go`), graph (`content.go`), FSRS-6 + FIRe (`fire.go`), placement test, HTTP API, CLI (`main.go`) | Engine work |
| `web/` | React + Vite UI | Engine work |

## Commands

| Command | Use |
|---|---|
| `./fire search <words>` | Find existing ideas to link to (`-pack id`, `-json`, `-n 20`). |
| `./fire show <code>` | Print one idea with its lesson, questions and links. |
| `./fire new <id> -title "…"` | Scaffold `packs/<id>/pack.json`. |
| `./fire validate [id…]` | Check packs; exit code 1 on errors. A pack is done only when this is clean. |
| `./fire docs` / `./fire docs -check` | Regenerate / verify generated docs. |
| `./fire progress export [file]` · `import <file>` · `reset -yes` | Learner progress. |

Flags go before positional words: `./fire search -pack quantifiers negation`.

## The learner asks for a topic or lessons

Follow **[`.agents/skills/add-topic/SKILL.md`](.agents/skills/add-topic/SKILL.md)** step by step. In short: search what exists, plan lessons from easy to hard, write `packs/<id>/pack.json` (format: [`docs/pack-format.md`](docs/pack-format.md)), link to existing ideas with weights from the rubric, solve every question yourself, run `./fire validate <id>` until clean, then tell the learner where it is in the app.

Rules:

- Write content only under `packs/`. Never edit generated files or another pack unless asked.
- Idea codes `<pack>.<topic>/<idea>` are permanent: progress is keyed by them. Fix a lesson freely; rename an id only if the learner agrees to lose progress on it.
- Lessons and questions are in the learner's language (the pack's `language`), unless asked otherwise.
- Do not commit packs: `packs/` is git-ignored on purpose — each learner's topics are their own.

## Changing the engine

- After Go changes: `cd server && go vet ./... && go test ./...`; after web changes: `cd web && npx tsc -p .`.
- Changed a route, a pack field, a field note or a skill: run `./fire docs` and commit the result; `./fire docs -check` must pass.
- New pack field: add it to the structs in `server/pack.go`, a note to `fieldNotes` in `server/docs.go` (a test fails otherwise), a check in `checkPack`, then `./fire docs`.
- Keep the progress format (`fire-progress-v1`) and idea codes backward compatible; FSRS parameters change only with a migration of stored memory.
- The server must stay localhost-only (Host check + `X-Requested-With: fire` on writes).
- Learning simulator: `cd server && SIM=1 SIM_PACKS=../packs go test -run TestSimulate -v .`
